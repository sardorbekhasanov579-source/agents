# Device access implementation plan
Goal: owner-directed PC and phone file operations through existing Telegram bot.
Architecture: scoped PC files + in-process queue/HTTP relay + Java Android SAF client.
Spec: ../specs/2026-11-17-device-design.md
Global constraints: Python3.11+, Android min26 target30, no external Python dependencies, 4MiB transfers, HTTPS phone endpoints, explicit folder grants.
Review focus: path escapes/symlinks; stale edit approvals; duplicate phone commands after lost network response; auth revocation; oversized files and invalid result payloads.
1. tests/test_devices.py: failing scoped path, backup/stale approval, pair/revoke/queue/result tests. Implement agentlar/devices.py and agentlar/phone.py, run tests.
2. Add device Telegram dispatch after existing owner check, main lifecycle relay setup, local folder selector BAT, tunnel launcher. Verify unauthorized requests cannot invoke actions and old tests pass.
3. Native Android Activity/Service: start stop, choose SAF tree, HTTPS pairing and polling, bounded search/get/put, response cache to avoid duplicate writes. Compile and sign APK; inspect manifest/signature. Real phone exercise remains user-side.
4. Independent review and regressions; all tests; package APK+source+instructions and persist ZIP.
