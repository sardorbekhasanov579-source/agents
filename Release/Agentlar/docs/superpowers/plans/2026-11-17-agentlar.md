# Agentlar Telegram Implementation Plan

> For agentic workers: execute task-by-task using superpowers:executing-plans.

**Goal:** Deliver a Windows ZIP with Telegram owner-only task execution and Gemini-backed software generation.
**Architecture:** Standard-library HTTP clients; guarded filesystem tools; durable JSON job state; background worker and responsive Telegram poller; interactive setup.
**Tech Stack:** Python 3.11+, Telegram Bot API, Gemini generateContent REST.
**Spec:** ../specs/2026-11-17-agentlar-design.md

## Global Constraints
No credentials embedded. Private owner messages only. Writes confined to per-job directory. Host execution disabled by default; exact-command approval if enabled. No claim of live validation.

## Review Focus
- Traversal, symlinks and Windows alternate streams: reject before file access.
- Unauthorized/group messages: no model requests, file access or command execution.
- Restart while working: mark interrupted; resume explicitly with bounded calls.
- Cancellation during model call: check before subsequent side effects.
- Partial model output or malformed JSON: fail visibly, retain files and history.

## Verification and decisions
- 22 offline tests passed; demo and compileall passed on Linux.
- Fresh reviewer found stale approval restoration and shutdown orphaning; regression tests added and fixed. Windows runner uses a kill-on-close job; Windows-specific behavior is not live-tested.
- Decision: ship a standalone ZIP rather than modify the older Agentlar package. This isolates the first Telegram version; old features are not migrated.
- Decision: Gemini model is selected from the user API account; no assumed model entitlement.
- Decision: internet search, PDF/Word parsing, voice, hosting and autonomous system-wide access are deferred; V1 is text-file software generation and optional explicitly approved commands.
- Native implementation plus one independent final reviewer; no repository push or deployment.
